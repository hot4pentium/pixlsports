---
name: Approved dashboard visual direction
description: The visual direction approved for future Pixl Sports supporter dashboard refinements.
---

Use the iPhone experience as the reference for shared PWA mobile screens: a white, lightly textured page canvas with navy/blue container surfaces. Prep, Track Stats, and Share keep their orange, light-blue, and green accents. Preserve useful desktop capabilities and bounded layouts rather than forcing a phone-sized interface everywhere.

**Why:** The user now wants the PWA to look and operate as closely as possible to iOS, saying the two currently feel like different products. This supersedes the earlier PWA-only navy backdrop direction.

**How to apply:** Align shared mobile journeys to the iOS canvas, containers, terminology, and actions. Preserve authored card artwork, account boundaries, and genuine browser-only or desktop capabilities.

Keep the PWA owner Showcase focused on HYPE Card, Edit Athlete Details (including the card photo), Fan Cheers, Share HYPE Card, and HYPE Card settings. Enter it from the dashboard card, without a separate Showcase tab or duplicate Edit HYPE Card button. Leave frame and lower-third customization out for now; preserve invited-athlete editing access.

**Why:** The user wants one consistent iOS/PWA product and explicitly deferred design customization to simplify the owner process.

**How to apply:** Use the five owner sections as the scope for parity work; do not reintroduce design-editor shortcuts into the owner preview.

On the PWA dashboard, omit the HYPE Card Share button and place a horizontal Fan Base button directly below the card at the same width. Keep sharing in Player Showcase.

**Why:** The user requested removing the dashboard Share shortcut and making Fan Base span the HYPE Card width.

**How to apply:** Preserve this layout across mobile and desktop card sizes, including the Fan Base details destination.

Offer a public HYPE Card QR code in the sharing section on both iOS and PWA, encoding the same public card link as Share. Keep this distinct from the private family Live Taps access QR.

**Why:** The user requested QR sharing for both platforms; the two QR types grant different access.

**How to apply:** Generate QR artwork locally and preserve the existing card sharing/privacy gate; displaying a QR must not publish a private card.

Use soft navy shadows beneath native blue containers and major cards to add separation from the white canvas. Keep shadows off small controls.

**Why:** The user asked for depth around the boxes without making the interface visually heavy.

**How to apply:** Use a consistent, restrained shadow on section surfaces, large cards, and tool panels; do not add elevation to every button or badge.

On the white native canvas, use a dark, contrast-checked green for text. Keep the bright lime for fills, icons, and text that sits on blue surfaces.

**Why:** The user found lime-green text difficult to read against white.

**How to apply:** Choose the semantic text color only for text on light surfaces; do not darken the brand fill or green accents on navy/blue cards.

Scope native control appearance to its surface: blue panels need light input text, explicit readable placeholders, and dark control appearance while the page and navigation remain light.

**Why:** After the white-canvas change, native light-mode defaults left Prep placeholders and Event Card date/time controls dark on blue; a parent white foreground alone did not reliably cover native controls.

**How to apply:** Apply the control color scheme locally to blue form panels or inputs, not to the whole screen. Avoid additional opacity reductions on controls already dimmed by their disabled state.

Keep the install action in the athlete overview header, not inside the Event Card. The paired mobile Event Card and HYPE Card should have equal face sizes and aligned top edges.

**Why:** The user requested moving “How to install” to the header and making the Event Card and HYPE Card equal.

**How to apply:** Preserve the paired-card alignment when changing labels, spacing, or installation controls; retain readable event details and usable card actions on narrow phones.

Keep the mobile Shoutouts & Replies summary card out of the overview grid. Surface the inbox from the page header with a bullhorn that glows when unread replies or Fan Shoutouts are available.

**Why:** The user asked to remove that card on mobile and make available shoutouts visible from the header.

**How to apply:** Keep the inbox reachable from the header; use the existing unread reply count and the available Fan Shoutouts list to control the glow.

For the desktop supporter dashboard, keep everything within one centered, bounded column with aligned section edges and consistent spacing. Keep a compact HYPE Card and the same mobile game-day message board together, a grouped athlete overview to the right, Quick Links beneath the HYPE Card, and Event Cards aligned below.

**Why:** The user requested a smaller desktop HYPE Card and the same mobile message board beside it, then rejected the scattered desktop composition as overwhelming and asked for centered content with properly aligned sections.

**How to apply:** Preserve mobile/desktop message and action parity using real event state, not a static badge substitute. Check full-screen centering and shared section boundaries at both narrow desktop and wide-screen widths; do not treat merely fitting three columns as sufficient visual verification.
