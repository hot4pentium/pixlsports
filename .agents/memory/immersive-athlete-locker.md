description: User-approved direction for the dedicated Pixl Sports Athlete Locker.
---

Keep the Locker off the supporter dashboard. Make the separate Player Showcase tab a jersey-first showcase based on the user's supplied photoreal jersey reference; do not duplicate the Locker there. Preserve existing public/shared Locker routes and account/permission behavior; do not add an Owner/Supporter role switch.

Equipment should appear as automatic rewards for meaningful return and usage milestones—such as distinct returns, first/tenth Event Cards, and first/fifth completed Stat Tracker games—instead of collecting badges.

**Why:** The user initially chose a full Locker experience, then preferred a photoreal jersey as the Player Showcase centerpiece instead of showing both jersey and Locker.

**How to apply:** Overlay current athlete details on the supplied photoreal jersey and keep Gear and Shoutouts actions on the showcase. Leave public Locker views, permissions, and milestone rules unchanged.

Build Your Kit should also use the photoreal jersey preview, without the earlier illustrated player over it.

**Why:** The user reported that the previous image was still showing in the kit editor and supplied a screenshot of the illustrated player covering the jersey.

**How to apply:** Keep the editor's preview jersey-first like Player Showcase. This does not request changes to the existing public/shared Locker artwork.

Parents are expected to build the athlete's site, while the athlete should be involved in making it their own.

**Why:** The user said the parent will basically build the site but wants to involve the student.

**How to apply:** Make athlete participation part of the parent-led creation and personalization flow without changing the existing account and permission model.

Leave the supporter dashboard focused completely on leading parents through the week; athlete expression belongs on the separate Player Showcase page, not within the dashboard.

**Why:** After seeing the combined dashboard, the user explicitly asked to move the Locker off it and provide a Player Showcase tab incorporating both sections.

**How to apply:** Preserve the dashboard's weekly recommendations and preparation/game-day/celebration actions on phones and desktop. Add navigation to Player Showcase without embedding its Locker or jersey presentation in the parent dashboard.

Parents can share a public Showcase link with recipients. The recipient view includes the photoreal jersey and a direct link to the public HYPE Card; event details follow existing visibility settings.

**Why:** The user chose a public Showcase for recipients and asked that it include a link or picture of the HYPE Card.

**How to apply:** Build public Showcase views from the sanitized fan-card endpoint, and keep owner/editor routes and private settings out of the recipient view.

Player Showcases must use a sport-appropriate jersey preview; American football includes a lace-up neckline. The owner Showcase should also make the Gear action visible for football athletes without sending them to soccer-only controls.

**Why:** The user reported that the football Showcase showed a generic jersey and omitted the Gear action.

**How to apply:** Keep sport-specific uniform details in both owner and recipient views. Football must have its own Gear controls, not be sent to the soccer-only editor.

Gear artwork for the supported sports should be photorealistic when earned and a white outline until earned.

**Why:** The user asked, “Are you able to supply photo realistic gear for our sports?” and requested “a white outline of gear until it is earned,” while choosing football Gear controls.

**How to apply:** Use actual white contours for locked equipment, not faded color photos. Keep earning enforced on the server and keep public visibility under parent control.

Show currently equipped, earned gear along the bottom of the jersey display, arranged on the table in the scene.

**Why:** The user asked that gear appear “along the bottom of the jersey. On the table.”

**How to apply:** Put full-color equipped items on the jersey's bottom display surface in owner and public views. Keep the full collection below, and respect parent-controlled public gear visibility.

Owner Gear controls must resolve the HYPE Card for the selected athlete and sport. If no matching card exists, the visibility toggle and Save action should remain responsive and explain how to complete card setup; never imply an unsaved draft was saved.

**Why:** The user reported that the Gear checkbox and Save button did not respond to touch. The editor had disabled both because its lookup found no matching HYPE Card.

**How to apply:** Include the current athlete identity in the owner lookup, preserve server validation of the selected invite, and provide a direct HYPE Card setup link when the profile has no match.
