---
name: Private iPhone Season Stats
description: Dashboard placement, private history ownership, and offline season analysis boundaries.
---

Season Stats is a dashboard feature card directly below Game Record, opening a
private native page with graphs, trends, comparisons, and game details.

**Why:** The user explicitly requested a dashboard feature card under the Game
Record box, separate from the HYPE Card.

**How to apply:** Keep access independent of public HYPE Card visibility. Preserve
the separation between athlete-tagged statistics and team scores/totals. Missing
athlete attribution and unentered scoreboards must not become invented zeros in
averages or comparisons.

Season history is the selected tracker project, not the sum of every saved
project. Pending device finals may augment that project but must not overwrite a
corrected cloud final when no tracker command is outstanding.

**Why:** Independent tracker saves can duplicate or represent different seasons.
Blindly merging them double-counts games; old device snapshots can undo an
owner's final corrections.

**How to apply:** Match project identity, verified account and sport. A first-ever
projectless offline final needs both a pending tracker command and the current
verified Event Card. Older prepared workspaces without project identity require
a connected refresh before unrestricted merging. Never discard their queues to
make a season report load.
