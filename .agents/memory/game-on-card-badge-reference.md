Use the supplied white physical lanyard badge graphic as the public Game On Card surface. Keep the slot unobstructed and put the event and athlete destination on the badge front, with the stats state on its reverse. The visible badge must have a complete rounded bottom, a slim surround, and legible printed text at phone scale; do not use a bulky square white rectangle.

**Why:** The user explicitly rejected a dark rectangular digital card, clarified that the content belongs on their badge image, and asked to enlarge its text for readability.

**How to apply:** When revising the shared public card, preserve the full rounded badge silhouette and white printed area, keep all lettering readable on phones, and avoid reverting to a generic sports panel or cropping off the lower edge.

The dashboard event badge must show the actual next upcoming Event Card, including its name and date/time. Its printed text must be substantially larger, not just the small generic artwork labels.

**Why:** The user reported that a tomorrow Event Card was absent from the badge and repeated that the badge text still needed to be larger.

**How to apply:** Preserve the lanyard artwork while displaying the current next event; do not treat blank generic artwork as a complete dashboard badge.

Native long-press image previews must retain the same current event details as the dashboard badge.

**Why:** The user confirmed the correct event appeared on the dashboard, but it disappeared when long-pressing for an enlarged image view.

**How to apply:** Verify the image independently from the surrounding page; visible page overlays alone do not satisfy the enlarged-view requirement.
