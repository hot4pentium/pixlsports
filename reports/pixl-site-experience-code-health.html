What works well

  • Clear public entry: Phone (402px) and desktop (1440px) previews show a legible season promise and distinct “Open Creative Studio” / “Explore the tools” actions. Navigation condenses on the phone without visible overflow. The guest Hype Card editor works as a visible four-step walkthrough; desktop shows editing and preview side by side, while mobile stacks them.
  • Relevant game-day hierarchy: The dashboard model considers upcoming, live, and completed stages rather than presenting one static list. Its code exposes direct tool actions and accounts for stale selections. Evidence: supporter-dashboard-model.ts:302-423; supporter-dashboard.tsx:932-1011.
  • Helpful state and failure language: The tracker distinguishes device-saved from cloud-saved work, offers retries/conflict choices, and Season Stats keeps edits in place after a failed correction. Hype Card media explains when it is available only on the device. Evidence: stat-tracker-page.tsx:240-296,1388-1427; season-stats-view.tsx:139-175,291-312; hype-card.tsx:2775-2822.
  • Sound underlying boundaries: API routes, database schema, generated clients, and feature models are separated. Local-first saves and revision conflict handling show deliberate data-loss protection, while lazy-loaded routes reduce initial feature loading. Evidence: App.tsx:162-215; stat-tracker-page.tsx:1578-1608; artifacts/api-server/src/routes/index.ts.

What deserves attention

ConfirmedWhole-workspace typecheck is red

pnpm run typecheck stops at artifacts/mockup-sandbox/src/components/mockups/live-tracker/RecipientView.tsx:42 with TS7030 (“Not all code paths return a value”). The main Studio typecheck passes when run independently. Because the root build runs the workspace typecheck first, this preview-only error blocks that release gate even though the main web artifact compiles.

ConfirmedThe default Studio test command misses unit tests

The Studio has 42 non-browser feature test files, but its test script hand-lists 30; 12 newer unit tests are omitted from that command. The 12 browser-test files are deliberately separate and should remain a separate tier. A passing default test run therefore does not mean all inexpensive feature checks ran. Evidence: artifacts/league-matrix-studio/package.json:10-22; source test-file inventory.

Risk, not proven defectCross-feature editing is concentrated

App.tsx is roughly 4,400 lines and owns navigation, account gating, schedule/checklist work, and several save paths. The Hype Card editor is roughly 3,600 lines and the tracker page roughly 2,100. Large files are not inherently poor code, but these particular files combine interaction state and persistence orchestration, raising the chance that a narrow change affects an unrelated flow. Extract one controller at a time with its existing tests; do not rewrite all three. Evidence: App.tsx:1976-2280,3110-3775,4320-4371; hype-card.tsx; stat-tracker-page.tsx.

Validate with usersMobile tool discovery and small controls

The signed-in dashboard mobile menu exposes the Hub and sign-out, while access to individual tools relies on cards and contextual actions. That may be a sensible simplification, but whether a returning supporter can promptly find Calendar, Tracker, or Season Stats is not established by source review. In the guest Hype Card phone preview, save and preview are icon-only (both have accessible labels) and several supporting labels are small; verify comprehension and readable text at real phone sizes before changing the navigation. Evidence: supporter-dashboard.tsx:932-1011; hype-card.tsx:2785-2811; phone screenshots inspected.

Ranked next steps

  1. Restore the workspace release check — Small. Fix the preview component’s missing effect return path and confirm the root typecheck is green. Benefit: release validation becomes trustworthy again.
  2. Run every fast Studio unit test by default — Small. Replace the manual 30-file list with test discovery restricted to non-browser tests; keep the expensive browser suites explicit. Benefit: new tests stop being silently excluded.
  3. Validate the signed-in mobile journey — Medium. With disposable fixtures, try “find the next game → track it → review final stats → make a Hype Card” on phone and desktop, recording missed actions, focus changes, and recovery. Benefit: turns the navigation concern into evidence before adding more UI.
  4. Extract one high-change orchestration boundary — Medium/Large. After the checks are green, separate a single schedule or checklist save controller from the main app without changing user behavior. Benefit: smaller, safer changes to local/cloud sync. Do not start with a broad refactor.
